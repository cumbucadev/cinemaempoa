# Reduce Production Docker Image Size Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Shrink the production Docker image (`Dockerfile.prod`, currently ~1.09GB) enough that a build no longer risks exhausting disk on the deploy server, and add a deploy-script safety net against the same failure mode.

**Architecture:** Move dev/test/lint-only Python packages out of the default `uv sync` dependency set, rewrite `Dockerfile.prod` as a two-stage build so the final image only contains the runtime venv (no `uv` binary, no apt cache), apply the same locale fix to `Dockerfile.dev` for consistency, and prune stale Docker images before (not just after) the deploy build.

**Tech Stack:** `uv` (dependency management/lockfile), Docker multi-stage builds, Debian `slim` base image, GitHub Actions (`appleboy/ssh-action`).

## Global Constraints

- Do not change the pinned versions of `requests` (`==2.32.3`), `jiter` (`==0.11.1`), or `jinja2` (`==3.1.6`) — these are pinned for `atomic-agents`/`instructor` dependency resolution (see `CLAUDE.md`). Moving a package between dependency groups must not change its version specifier.
- Stay on `python:3.14-slim` (glibc) for both build and runtime stages — do not switch to Alpine/musl (risk of broken/slow builds for `numpy`/`pandas`/`pillow`).
- The production image must still support `docker exec cinemaempoa_flask flask --app flask_backend fetch-movie-metadata` and `inspect-movies` after these changes — do not remove `litellm`, `llama-index`, `pandas`, `numpy`, or any of their dependencies.
- No fixed target size (e.g. not chasing "<100MB") — validate via before/after size comparison, not a hard number.
- `pyproject.toml`/`uv.lock` changes must keep `uv sync --frozen` (no `--no-dev` flag) working unchanged for CI (`ci.yml`) and `Dockerfile.dev`.

## File Structure

- **Modify `pyproject.toml`** — move `pytest`, `ruff`, `djlint`, `pre-commit`, `faker`, `debugpy` from `[project] dependencies` into `[dependency-groups] dev`.
- **Modify `uv.lock`** — regenerated by `uv lock` to reflect the group move (not hand-edited).
- **Modify `Dockerfile.prod`** — rewritten as a two-stage build (`builder` + runtime), with the `locales`/`locale-gen` fix and `--no-dev` sync.
- **Modify `Dockerfile.dev`** — same `locales`/`locale-gen` fix applied to its single-stage build; no other changes.
- **Modify `.github/workflows/deploy-server.yml`** — add an image-prune step before the build step.

### Task 2: Rewrite `Dockerfile.prod` as a multi-stage build

**Files:**
- Modify: `Dockerfile.prod` (full rewrite)

**Interfaces:**
- Consumes: `uv sync --frozen --no-dev` behavior established in Task 1 (must be merged/present before this task's size comparison is meaningful).
- Produces: a `cinemaempoa-flask` image usable by `docker-compose.production.yml` / `docker-compose.shared.yml` — same `EXPOSE 8080` and `CMD` as before, so no compose file changes are needed.

- [ ] **Step 1: Record the baseline image size**

Run: `docker build -f Dockerfile.prod -t cinemaempoa-flask:baseline . && docker image inspect cinemaempoa-flask:baseline --format='{{.Size}}'`

Expected: prints a byte count (should be roughly `1.0-1.1e9`, matching the ~1.09GB reported in issue #197). Note this number down — it's the "before" figure for Step 5.

- [ ] **Step 2: Rewrite `Dockerfile.prod`**

Replace the entire contents of `Dockerfile.prod` with:

```dockerfile
FROM python:3.14-slim AS builder

WORKDIR /app

COPY --from=ghcr.io/astral-sh/uv:latest /uv /uvx /usr/local/bin/

ENV UV_PROJECT_ENVIRONMENT=/opt/venv
ENV PATH="/opt/venv/bin:$PATH"

COPY pyproject.toml uv.lock .
RUN uv sync --frozen --no-dev

FROM python:3.14-slim

WORKDIR /app

RUN apt-get update && \
    apt-get install -y --no-install-recommends locales tzdata && \
    sed -i '/pt_BR.UTF-8/s/^# //g' /etc/locale.gen && \
    locale-gen && \
    apt-get clean && \
    rm -rf /var/lib/apt/lists/*

ENV TZ="America/Sao_Paulo"
ENV LC_ALL pt_BR.UTF-8
ENV LANG pt_BR.UTF-8
ENV LANGUAGE pt_BR.UTF-8

# venv lives outside /app so it survives the bind mount (docker-compose.production.yml
# and docker-compose.shared.yml both mount the repo over /app at runtime)
ENV PATH="/opt/venv/bin:$PATH"

COPY --from=builder /opt/venv /opt/venv
COPY . .

EXPOSE 8080
CMD ["gunicorn", "flask_backend:create_app()", "--workers", "4", "--bind", "0.0.0.0:8080", "--timeout", "120"]
```

- [ ] **Step 3: Build the new image**

Run: `docker build -f Dockerfile.prod -t cinemaempoa-flask:trimmed . && docker image inspect cinemaempoa-flask:trimmed --format='{{.Size}}'`

Expected: build succeeds; the printed byte count is meaningfully smaller than the Step 1 baseline (expect at least a few hundred MB smaller, given `locales-all` alone is typically 200-300MB and the dev tooling removal is ~60-70MB more).

- [ ] **Step 4: Verify dev tooling is absent from the trimmed image**

Run: `docker run --rm cinemaempoa-flask:trimmed python -c "import pytest" 2>&1; docker run --rm cinemaempoa-flask:trimmed python -c "import faker" 2>&1; docker run --rm cinemaempoa-flask:trimmed which uv 2>&1`

Expected: both `import` commands fail with `ModuleNotFoundError`, and `which uv` prints nothing / exits non-zero (the `uv` binary only exists in the `builder` stage, not the final image).

- [ ] **Step 5: Verify the runtime ML/LLM stack still works**

Run: `docker run --rm cinemaempoa-flask:trimmed python -c "import litellm, llama_index, pandas, numpy; print('ok')"`

Expected: prints `ok` with no import errors — confirms `--no-dev` didn't accidentally strip a runtime dependency needed by `fetch-movie-metadata`/`inspect-movies`.

- [ ] **Step 6: Smoke-test the app boots and serves a request**

Run:

```bash
docker run -d --name cinemaempoa-smoke -p 18080:8080 cinemaempoa-flask:trimmed \
  sh -c "flask --app flask_backend init-db && flask --app flask_backend db-upgrade && gunicorn 'flask_backend:create_app()' --workers 1 --bind 0.0.0.0:8080"
sleep 5
curl -sf -o /dev/null -w '%{http_code}\n' http://localhost:18080/
docker logs cinemaempoa-smoke
docker rm -f cinemaempoa-smoke
```

Note the single quotes around `flask_backend:create_app()` — required so the container's `sh` treats the parentheses as literal characters in gunicorn's argument rather than shell function/subshell syntax.

Expected: `curl` prints `200`. Clean up the container either way with the final `docker rm -f` (already included above).

- [ ] **Step 7: Clean up local test images**

Run: `docker rmi cinemaempoa-flask:baseline cinemaempoa-flask:trimmed`

Expected: both tags removed; keeps the local Docker disk usage from this validation from lingering.

- [ ] **Step 8: Commit**

```bash
git add Dockerfile.prod
git commit -m "perf: rewrite Dockerfile.prod as multi-stage build, drop locales-all"
```
